# V1.0 验收清单

本清单区分自动测试和真实环境验收。未勾选表示需要在目标环境执行，不表示已经完成。建议先用两个测试网站、两个邮箱、两个独立浏览器以及两台 Bark 设备。

## 已在本机验证

- [x] 后端隔离/权限/去重/规则/重试等 32 项自动化测试通过。
- [x] 前端 TypeScript 检查和生产构建通过。
- [x] Docker 官方 Compose 配置校验通过（服务环境文件未加载，使用示例变量）。
- [x] 不同 Origin 的宿主网站嵌入、展开、发送及刷新后恢复历史。
- [x] 初始 Alembic 迁移在独立 SQLite 数据库成功执行。
- [x] 后台登录、查看测试历史和 Markdown 展示。
- [x] 独立聊天页输入邮箱建立会话、WebSocket 连接、发送客户消息。
- [x] 后台实时出现新消息，后台回复实时进入聊天页，刷新可恢复当前历史。
- [x] 桌面 1440px 与移动尺寸的响应式结构检查。
- [x] Python 依赖及前端生产依赖安全公告审计未发现已知漏洞（2026-10-22，非持续保证）。

## 部署与持久性

- [ ] 使用真实 `.env` 的 `docker compose config --quiet` 和完整镜像构建通过。
- [ ] VPS 上各服务健康，migrate 成功退出，域名 HTTPS 证书有效。
- [ ] `python3 scripts/smoke.py https://客服域名` 通过。
- [ ] 初始管理员登录；修改密码后旧会话失效；退出与 12 小时过期正确。
- [ ] PostgreSQL CI 并发测试通过，多个同时首次咨询只生成一个客户和长期会话。
- [ ] 重启 API、worker、PostgreSQL 后历史、图片、站点配置仍存在。
- [ ] 备份完成并在隔离环境恢复成功；旧图片和加密配置可访问。
- [ ] 目标 1C2G / 2C2G VPS 上完成业务预期并发、峰值上传、队列延迟和磁盘增长观察。

## 网站、会话和移动端

- [ ] 创建 A、B 两个网站，单站筛选和全站列表正确；禁用网站立即拒绝新旧访客凭证。
- [ ] 自定义名称、主题色、标题、Logo、欢迎语生效，接入代码和独立链接可用。
- [ ] HTML、WordPress 正常加载组件，最小化、展开、未读提示正常且不影响宿主布局。
- [ ] iPhone Safari、Android Chrome、桌面主流浏览器正常使用；软键盘不挡住输入与发送。
- [ ] Safari 第三方 Cookie 受限时仍能建立会话、刷新恢复和接收回复。
- [ ] 同浏览器 A/B 网站凭证隔离；清除 A 站存储后重新填同邮箱不能读旧历史。
- [ ] 在测试数据库将旧 VisitorSession.expires_at 改为过去（不要改生产记录），旧 token 的 REST/WS/图片均被拒绝。
- [ ] 过期后同邮箱新会话没有旧记录，后台仍显示完整历史；同邮箱使用原 Telegram 话题。
- [ ] 猜测邮箱、修改会话 ID、站点 ID、附件 ID 不能越权读取。
- [ ] 两台设备用同邮箱建立不同会话，确认新客服回复仅发给最新有效会话，符合 V1 规则。

## 消息、历史和管理

- [ ] 普通文字、Emoji、Markdown 标题/粗斜体/链接/列表/行内代码/代码块/图片均展示正确。
- [ ] 原始 HTML、javascript 链接、伪图片和 SVG 均无法执行；图片超限被拒绝。
- [ ] 客户、后台双方图片可预览、点击大图；其他客户不能下载私有图片。
- [ ] 断网、恢复网络后自动重连；失败发送重试不重复入库。
- [ ] 邮箱/消息内容/网站/日期/状态搜索正确；超过 100 条的会话和历史可翻页。
- [ ] 待处理/处理中/已解决切换、未读计数、内部备注保存正确。
- [ ] 快捷回复创建/修改/分类/删除与插入发送正确。
- [ ] 每网站独立首次/非工作时间/关键词自动回复、时区、跨午夜工作时间、冷却和启停正确。
- [ ] 自动回复持久化且同步 Telegram，不循环触发。

## Telegram 真实联调（重点）

- [ ] 连接测试识别论坛群组和话题权限，Webhook 成功注册且 secret 检查有效。
- [ ] 同网站、同标准化邮箱首次消息并发进入同一个话题；不同站点同邮箱进入不同话题。
- [ ] Cookie/存储清除和 30 天过期不改变话题映射。
- [ ] 超长话题标题截断但数据库映射仍正确。
- [ ] 客户文本、Emoji、图片转发正确并带站点/邮箱标识。
- [ ] 授权客服直接在话题发送文字、照片与说明，正确到达当前客户端。
- [ ] Telegram 粗斜体、代码、超链接安全转换；Emoji 前后的 UTF-16 实体偏移正确。
- [ ] 非白名单用户、其他群组、Bot 自身、匿名管理员/频道消息不能冒充客服。
- [ ] 重复 update_id 不重复入库；worker 重启后可继续处理已持久化更新。
- [ ] `/close`、`/reopen`、`/quick`、`/quick 标题或ID` 正常，模板正文显示且同步网站记录。
- [ ] 客户再次发消息会重开已关闭话题；后台状态同步变化。
- [ ] 删除话题、撤销 Bot 权限或网络故障时，客户消息仍在 DB、投递日志出现错误。
- [ ] 手动修复话题映射并重试，积压消息能重新发送；不会静默丢失或擅自创建重复话题。
- [ ] 模拟创建话题响应未知时，人工核对并修复映射后可恢复。

## Bark 真实设备联调

- [ ] 英文逗号/换行批量添加与逐台编辑、命名、禁用、删除正确。
- [ ] 全局关闭后不发普通通知，启用设备均可收到新客户消息任务。
- [ ] 一台无效设备失败时，其他设备任务继续执行；错误与重试可见。
- [ ] 单设备、全部测试显示设备名、HTTP 状态码、错误和时间；API 接受与设备实际到达分别核对。
- [ ] 通知带网站/邮箱/摘要，点击进入相应后台会话；未登录时先登录再跳转。
- [ ] 聊天组件、公开接口和配置列表不包含 Bark 密钥或 Bot Token。
